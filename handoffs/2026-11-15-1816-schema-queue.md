## Files
Each file's state, and whether it carries over to D1/SQLite:

- src/db/schema.ts — modified — **done for Postgres; needs rewriting for D1.**
  - What has to change: it uses `drizzle-orm/pg-core` with `pgEnum`, `uuid`, `jsonb` and `timestamptz`. D1 needs `sqlite-core`, with text plus check constraints standing in for enums, text or integer IDs, and JSON stored as text.
  - What carries over: the table and column design, the unique indexes and the partial unique indexes (SQLite supports partial indexes). The once-per-user and one-active-automation rules work the same way on SQLite.
- src/db/client.ts — modified — **done for Postgres (postgres.js); needs rewriting for D1.** I added the `Tx` and `DbOrTx` types. D1 has no interactive transactions, only `batch()`, which affects the queue design.
- src/db/queue.ts — created — **done for Postgres; does not port as written.** SQLite has no `FOR UPDATE SKIP LOCKED`. On D1, claiming would need a single `UPDATE … WHERE id IN (SELECT … LIMIT n) RETURNING *`, which relies on D1's single-writer serialization, or a different queue such as Cloudflare Queues. The ownership-guard idea (`locked_by = $me AND status = 'running'`) and the rule to exclude `SENDING` deliveries from recovery both carry over.
- src/db/test-utils.ts — created — **done for Postgres; does not port.** It creates and drops a database per test file over a Postgres admin connection. The fake-data fixture helpers at the bottom of the file can be reused.
- src/db/queue.db.test.ts — created — **done for Postgres (10 tests, passing).** The test cases are reusable as a spec. The concurrency test assumes separate connection pools.
- src/db/schema.db.test.ts — created — **done for Postgres (7 tests, passing).** The constraint cases are reusable as a spec. The assertions check Postgres error codes (`23505`, `23514`) and `constraint_name`, which SQLite reports differently.
- drizzle/0000_initial_schema.sql — created — **Postgres DDL; discard and regenerate for SQLite.**
- drizzle/0001_seed_app_settings.sql — created — **done.** The SQL (`INSERT … ON CONFLICT ("id") DO NOTHING`) is valid SQLite, but it should be regenerated alongside the new initial migration.

- drizzle/meta/0000_snapshot.json — created — **Postgres snapshot; discard.**
- drizzle/meta/0001_snapshot.json — created — **Postgres snapshot; discard.**
