## Phase
1. `src/db/schema.ts`: tables `instagram_accounts`, `automations`,
   `webhook_events`, `deliveries`, `jobs`, `operational_events` with PRD §9
   fields, plus an `app_settings` single-row table (`id` = 1 check,
   `sends_paused boolean default false`, `retention_days int default 30`,
   `last_webhook_at`, `last_reconciliation_at`, `worker_heartbeat_at`).
   - Postgres enums for delivery status (the 9 FR-08 values), public reply
     status (`not_requested|pending|sent|failed`), job status
     (`pending|running|done|failed|cancelled`), trigger type, match mode,
     connection status, source (`webhook|reconciliation|manual`).
   - `deliveries`: unique (`instagram_account_id`, `comment_id`); index
     (`automation_id`, `status`); index `comment_created_at`; index
     (`automation_id`, `commenter_igsid`). Add a **partial unique index**
     enforcing once-per-user: unique (`automation_id`, `commenter_igsid`)
     where `counts_toward_once_per_user` is true — a boolean column set true
     on the delivery that claims the user's slot (so later comments by the
     same person insert as SKIPPED with it false). Note in a comment how this
     makes the rule transactional.
   - `automations`: partial unique index — one active automation per
     (`instagram_account_id`, `media_id`) where `is_active`.
   - `webhook_events`: unique `event_key`; store only a minimal `payload`
     jsonb (the fields matching needs), not raw bodies.
   - `jobs`: unique (`job_type`, `delivery_id`) to stop duplicate enqueues;
     index (`status`, `run_after`); `last_error` text.
   - Tokens: `encrypted_access_token` is text holding ciphertext; no plaintext column.
2. `pnpm db:generate` → commit the SQL in `drizzle/`. You may run
   `pnpm db:migrate` against the **local docker** DB only.
3. `src/db/queue.ts`: `enqueueJob(tx|db, { jobType, deliveryId, runAfter })`
   (ON CONFLICT DO NOTHING), `claimJobs(db, { workerId, limit, now })` using
   `UPDATE … WHERE id IN (SELECT … WHERE status='pending' AND run_after <= now
   ORDER BY run_after FOR UPDATE SKIP LOCKED LIMIT n) RETURNING *` setting
   `running`, `locked_at`, `locked_by`, `attempts+1`; `completeJob`,
   `rescheduleJob(id, runAfter, error)`, `failJob`; and
   `recoverAbandonedJobs(db, { olderThanMs, now })` that returns stale
   `running` jobs to `pending` **only** for jobs whose delivery is not in
   `SENDING` (a job abandoned mid-send must not be retried — the delivery
   worker phase will turn those into DELIVERY_UNKNOWN; leave a clear TODO and
   return them separately).
4. `src/db/test-utils.ts`: helper that creates a throwaway schema/database
   per test file (or truncates), runs migrations, and tears down; reads
   `DATABASE_URL` with a default matching docker-compose.
5. `src/db/queue.db.test.ts`: enqueue dedupe; two concurrent `claimJobs`
   (separate connections) never return the same job; `run_after` respected;
   reschedule; abandoned-job recovery incl. the SENDING exclusion;
   `deliveries` unique comment constraint; once-per-user partial index
   rejects a second slot-claiming row; one-active-automation-per-media.
