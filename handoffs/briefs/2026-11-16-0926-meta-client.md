## Goal
`src/meta/` is a Workers-runtime Instagram Graph client with no business rules
and no database access: webhook GET verification and POST signature check,
OAuth token exchange/refresh, the reads FewChat needs, private and public
reply sends, and a classifier that turns every response (or transport failure)
into one typed outcome the delivery consumer (2b) can act on. Done = every
fixture in the fact sheet's §2.3 and §7.3 plus the §7.3 edge cases has a unit
test, and `pnpm lint && pnpm typecheck && pnpm test && pnpm build` pass.

## Context
- Spec: `docs/research/meta-api.md` §1 (version), §2 (OAuth/tokens), §4
  (reads), §5.2 (verify + signature), §6 (private/public reply contracts), §7
  (limits, the classification table, synthetic fixtures). `docs/PRD.md` §§7.3,
  8.3, 10 for the outcome rules. Treat the fact sheet's **UNVERIFIED** rows as
  unverified: classify those tuples as `unknown` with the raw tuple preserved.
- `docs/adr/0002-free-first-cloudflare.md` Decision 6 overrides the fact
  sheet's `timingSafeEqual`: verify with `crypto.subtle.verify("HMAC", …)` on
  the raw body bytes, after a **streaming** 32 KB body cap, before any JSON
  parse. Pattern: `spike/src/crypto.ts` `verifySignature`. Reject a header that
  isn't `sha256=` + exactly 64 hex chars; missing/invalid fails closed.
- Previous phase: `handoffs/merged/2026-11-16-0922-cf-infra.md`. Code runs in
  the Worker (Web APIs only: `fetch`, `crypto.subtle`, `TextEncoder`; no
  `node:*`). Unit tests run in Vitest's `unit` project on Node 24, which has
  the same Web APIs.
- Rulings already made (don't reopen):
  - `fetch` is injected (a `fetch`-shaped parameter or client option), so tests
    never touch the network and use no mocking library.
  - Graph version and base URL come from the caller (`META_GRAPH_API_VERSION`
    is in `src/config/env.ts`); no env reads inside `src/meta/`.
  - Outcome type for sends is a discriminated union, at least: `sent`
    (with the response ids), `rate_limited` (with `retryAfterMs` when
    `Retry-After` is present), `token_invalid`, `ineligible`,
    `policy_blocked`, `invalid_request`, `unknown` (send outcome cannot be
    established — 5xx, non-JSON, 200 without the expected id, abort/timeout
    after dispatch, codes 1/2, any unmapped tuple). Each non-`sent` outcome
    carries `{ httpStatus, code, subcode, type, isTransient, fbtraceId,
    message }` with the message truncated (≤ 300 chars) and access tokens
    redacted from any URL or text it contains.
  - A failure **before** dispatch (e.g. building the request threw) is
    distinct from `unknown`; name it `not_sent`.
  - Reads (account, media, comment) may retry once on 5xx/transport errors;
    sends never retry inside the client.
  - Never match English error prose. Don't add `10900`/`10903` as known
    Instagram tuples (§7.2); the §7.3 `10900` fixture classifies as `unknown`.
  - Tokens go in an `Authorization: Bearer` header or the documented body/query
    parameter exactly as §2/§6 specify, and never into thrown error messages.

## Phase
1. `src/meta/webhook.ts`: `verifySubscription(params, verifyToken)` →
   challenge string or null; `readSignedBody(request, appSecret, { maxBytes =
   32_768 })` → `{ ok: true, body: Uint8Array }` or `{ ok: false, reason:
   "missing_signature" | "bad_signature" | "too_large" }`, reading the stream
   with a running byte count (don't trust `Content-Length`).
2. `src/meta/errors.ts`: `classifySendResponse` / `classifyReadResponse` from
   status + headers + body text, and `classifyTransportError(error,
   { dispatched })`. The table in §7.2 is the mapping.
3. `src/meta/client.ts`: `createMetaClient({ fetch, baseUrl, version })` with
   `exchangeCode`, `exchangeLongLived`, `refreshToken`, `getAccount`,
   `getMedia`, `getComment`, `subscribeAccount`, `sendPrivateReply`,
   `sendPublicReply`, following the endpoint shapes in §2, §4, §5.1, §6. An
   `AbortSignal` / timeout option on sends; a timeout after dispatch is
   `unknown`.
4. `src/meta/fixtures.ts`: the §2.3 and §7.3 fixtures as typed constants
   (fake values only, as written there), plus a helper that signs a fake body
   with a test-only fake secret.
5. Tests (`src/meta/*.test.ts`): signature valid / tampered byte / whitespace
   change / wrong secret / missing / malformed header / 33 KB body with a lying
   `Content-Length`; subscription verify ok and wrong token; every §7.3 fixture
   → its outcome; `Retry-After` parsed; non-JSON 5xx, 200 without id, abort
   after dispatch → `unknown`; a request-building failure → `not_sent`; a
   token never appears in any outcome's `message` (assert on a token in the
   URL and in the body); read retries once on 503 then succeeds.
6. `src/meta/README.md`: the outcome union and what 2b should do with each
   (one line each), and which classifications are UNVERIFIED pending the
   user's live Phase 0 test.
