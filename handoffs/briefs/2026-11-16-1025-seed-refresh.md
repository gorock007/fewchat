## Goal
The user can put their real Instagram account and one automation into a local
or remote D1 **without the dashboard or OAuth** (those are Step 4), so the
Step 3 live Meta test can run; and a connected account's long-lived token is
refreshed by the cron before it expires. Done = `pnpm seed --help` documents a
working flow that, against local D1 and a fake Meta origin in tests, creates an
encrypted account row (subscribed to webhooks) and an active automation; the
sweep refreshes a due token exactly once; and `pnpm lint && pnpm typecheck &&
pnpm test && pnpm build` pass.

- Rulings already made (don't reopen):
  - **Seed CLI** (`scripts/seed.ts`, run as `pnpm seed`, no new dependencies:
    bundle with the existing `esbuild` dev dep or run with Node 24's type
    stripping, whichever works with the `@/` imports it needs):
    - Subcommands `account` and `automation`. Flags: `--local` (default) or
      `--remote`, `--config <wrangler file>` (for the git-ignored
      `wrangler.deploy.jsonc`).
    - `account`: reads the long-lived token from **stdin only** (never a flag,
      never echoed), reads `TOKEN_ENCRYPTION_KEY` / `META_GRAPH_API_VERSION`
      from the environment or `.dev.vars`, calls `getAccount` to get the IG
      user id + username, calls `subscribeAccount` (record the result in
      `webhook_subscription_status`; a failure doesn't stop the seed),
      generates the local row id, encrypts with it, and upserts on
      `instagram_user_id` (re-seeding replaces the token and sets `connected`).
      `--expires-in <seconds>` defaults to 60 days.
    - `automation`: `--media <id> --keyword <word>` (repeatable) or `--any`,
      `--match exact|whole_word|contains`, `--url <resource url>`,
      `--message <template>` (default `DEFAULT_DM_TEMPLATE`), `--once-per-user`;
      validates with `validateResourceUrl` / `validateTemplate`; deactivates any
      other active automation on that media first (the partial unique index).
    - Writes go through `wrangler d1 execute <db> --local|--remote [--config]
      --file <tmp.sql>` with the SQL file in a fresh temp dir, deleted after.
      Ciphertext may appear in that file; the plaintext token must never reach
      disk, argv, stdout, or an error message.
    - Prints only: account username + IG user id + subscription result, or the
      automation id. `--help` lists the Step 3 flow (seed account → seed
      automation → comment from the three test accounts).
  - **Token refresh** in the sweep, after quarantine and before pending rows:
    - New nullable columns on `instagram_accounts`: `token_refreshed_at` and
      `token_refresh_attempted_at` (epoch ms). One generated migration
      (`pnpm db:generate`, next number); the seed sets `token_refreshed_at` to now.
    - Due = `connected`, token present, `token_expires_at - now < 7 days`,
      `token_refreshed_at` ≤ now − 24 h, and `token_refresh_attempted_at` null
      or ≤ now − 1 h. At most **1** account per tick.
    - Set `token_refresh_attempted_at` (conditional on the ciphertext read)
      before calling `refreshToken`. Success → new envelope, `token_expires_at`
      from `expires_in`, `token_refreshed_at` = now, all conditional on the old
      ciphertext. `token_invalid` / `permission_denied` → `markNeedsReconnect`
      (conditional, as 2b does). Anything else → leave it; retried after 1 h.
    - Never log the token; the sweep's log line gains `refreshed` / `refresh_failed` counts.
