An empty-but-real FewChat skeleton at the repo root: Next.js App Router + Tailwind + shadcn/ui, Drizzle on postgres.js, lazy zod env, Vitest (unit/db projects), Playwright smoke test, Postgres via docker compose, a Dockerfile, and folders that enforce the PRD's layer separation. No product features.

## What changed
- **Next.js 16.4.6** (create-next-app output, generated in scratch and copied in so README/AGENTS.md/.gitignore weren't overwritten). App Router, `src/`, Node runtime, `output: "standalone"`. The generator's `cacheComponents`/`partialPrefetching` and Tailwind v4 via `@tailwindcss/turbopack` are kept, so there's no `postcss.config.mjs`.
- **TypeScript** `strict` + `noUncheckedIndexedAccess`. `typecheck` is `next typegen && tsc --noEmit`, because Next 16's global `LayoutProps`/route types only exist after typegen. Without it, a clean checkout fails typecheck.
- **shadcn/ui** `init -d`: `components.json` (style `base-nova`, which is on Base UI), `src/components/ui/button.tsx`, `src/lib/utils.ts`. Current shadcn takes `cn` from the official `cn` package (shadcn-ui/cn) rather than clsx + tailwind-merge. It also adds `shadcn` as a dependency because `globals.css` imports `shadcn/tailwind.css`.
- **Home page**: plain "FewChat — Less automation. Just what you need." The layout sets the title/description, and the Geist font var is renamed to `--font-sans` to match shadcn's tokens. The default Next SVGs were removed from `public/`, and `public/.gitkeep` keeps the folder because the Dockerfile copies it.
- **Env** (`src/config/env.ts`): zod schema for all 9 vars, validated lazily by `getEnv()`. `parseEnv()` errors name the bad fields and never print values.
- **DB**: `drizzle.config.ts` loads `.env` if present (Node's `process.loadEnvFile`) and writes migrations to `./drizzle`. `src/db/client.ts` connects lazily via `getDb()`. `src/db/schema.ts` is a comment plus `export {}`.
- **Layer folders**: each has a one-line `README.md` stating its role: `src/meta`, `src/domain`, `src/db`, `src/worker`, `src/app`. There's no `index.ts` because a comment-only file fails `isolatedModules`.
- **Worker** (`src/worker/main.ts`): logs "worker started", stays alive, and exits 0 on SIGTERM/SIGINT.
- **Vitest 5** projects: `unit` covers `src/**/*.test.ts` minus `*.db.test.ts`, and `db` covers `src/**/*.db.test.ts`. `pnpm test` runs unit only. `test:db` uses `--passWithNoTests`. There are 2 unit tests, for `parseEnv`.
- **Playwright**: `e2e/home.spec.ts`; `webServer` runs `pnpm dev`. It isn't part of `pnpm test`, and no browsers were downloaded.
- **Docker**: `docker-compose.yml` has `db` (postgres:17, `pg_isready` healthcheck, `db-data` volume, port 5432, local-only credentials `fewchat`/`fewchat`) plus commented `app`/`worker` stubs. The `Dockerfile` is multi-stage (deps → build → standalone runner, non-root user) and has a `.dockerignore`.
- **Lint/format**: Next's flat ESLint config + `eslint-config-prettier`. Prettier uses defaults. `.prettierignore` skips docs/, handoffs/, .claude/, *.md and the lockfile. Extra scripts: `format` and `format:check`.
- **Packages**: `@types/node` was bumped from ^20 to ^22 to match `engines.node >=22`. `pnpm-workspace.yaml` adds `esbuild: true` to `allowBuilds`, needed by tsx/vitest/drizzle-kit; pnpm 12 refused the install without it.
