## What the user asked
Build the scoped Meta HTTP adapter from the completed Cloudflare infrastructure: subscription/signature verification, OAuth, reads, subscriptions, private/public replies, conservative error classification, synthetic fixtures and unit tests.

## What changed
- Webhook GET verification returns the unchanged challenge only for matching mode/token. POST verification caps streamed bytes at 32,768 independent of Content-Length, cancels oversized streams, validates the signature header and verifies HMAC with Web Crypto over the original bytes before any JSON parsing.
- Added `createMetaClient({ fetch, baseUrl, version })` with all nine requested methods plus `getComments` for the fact sheet's reconciliation edge. Resource requests are versioned, token endpoints unversioned, and code exchange uses the documented separate API host. No network mocking library, environment reads, database access or business rules.
- Validated short-token array/flat variants, long-token expiry, professional account `user_id`, media/comment fields and response IDs. Optional fields stay optional; IDs remain strings. Pagination returns cursors and reconstructs requests on the configured host instead of following provider next URLs.
- `kind` discriminates outcomes: `sent`, `rate_limited`, `token_invalid`, `permission_denied`, `ineligible`, `policy_blocked`, `invalid_request`, `unknown`, `not_sent`. `ineligible` is reserved and not emitted without verified evidence. Unverified 10900/10903/2534025 mappings remain unknown with the raw numeric tuple preserved. Permission errors have their own explicit terminal outcome.
- Every failure contains nullable HTTP/code/subcode/type/transient/trace fields and a sanitized message capped at 300 characters. Known credentials are redacted from prose and URL-encoded values, with additional structured-token/Bearer redaction. Malformed Unicode credentials cannot break the diagnostic path.
- Sends, token operations and subscription writes never retry. Account/media/comment reads retry once after 5xx/transport errors. Abort/timeout covers fetch and response consumption, cancels pending response streams and yields unknown after dispatch; pre-dispatch construction/cancellation yields not_sent. Default timeout is 30 seconds.
- Added typed synthetic fact-sheet token/error/comment/webhook/success fixtures and a fake-secret signing helper. Added 113 Meta tests, including all supplied token/error fixtures, signature edge cases, lying Content-Length, Retry-After seconds/date, request contracts, safe read retry, send uncertainty/no-retry, credential redaction, fixed-clock seven-day timestamp handoff to the existing domain policy, and the review regressions below.
- Review fixes: error-shaped responses below HTTP 400 always classify as `unknown`, including 200 plus code 4 or mixed success/error IDs. All 3xx responses are failures. Known 4xx rejections and ordinary HTTP 429 throttling retain their mappings; existing ambiguous/unverified tuples remain conservative.
- Every client Request now explicitly uses `redirect: "manual"`. Tests cover all ten methods, including a 302 from `exchangeLongLived`, verifying no second request and no accepted redirect response.
- `createMetaClient` now rejects invalid/non-HTTPS Graph origins immediately, with a generic credential-free error. Per-request version/build failures still return `not_sent`.
- OAuth code validation, normalization and redaction-secret collection now happen inside the guarded build path. Undefined, null, non-string, blank and fragment-only codes return `not_sent`. Query-token operations now validate access tokens in build; both sends validate nonempty comment IDs/text and tokens before dispatch.
- Response consumption now counts actual bytes against a 1 MiB cap before decoding/JSON parsing. Overflow cancels the stream and returns an `unknown` failure with the observed HTTP status, without a read retry. Tests cover sends, reads and tokens, lying Content-Length, the exact limit, one-byte overflow and multibyte UTF-8.
- Removed the synthetic caller-persistence failure test as requested; persistence and quarantine behavior is entirely 2b's test responsibility.
- README documents the API, each consumer action, input validation, HTTPS/manual redirects, body cap, unverified mappings and remaining Phase 0/2b responsibilities.
